# PolyTime — ready-to-run build for cPanel

This branch (`deploy`) is a **pre-built** copy of the app. Nothing needs to be
installed or built on the server: pull it, point a Node.js app at it, restart.
It is generated by `npm run build:deploy` on the `main` branch — never edit
files here by hand, they are replaced on every build.

```
node_modules/   packages the app and crawler need (already installed)
server/         ← the cPanel "Application root"
  server.js     ← the "Application startup file"
  .next/  public/  crawler/  lib/
  data/         created on first start: the SQLite database (app.db)
  .env.production   you create this once on the server (see below)
```

`data/` and `.env.production` are ignored by git, so pulling a new build never
touches your database or settings.

## Requirements

- cPanel with **Setup Node.js App** (CloudLinux Node.js Selector).
- **Node.js 22.13 or newer** (24 recommended — the build is made with 24). The
  app uses Node's built-in SQLite, which older versions don't have.

## First-time setup

### 1. Pull the code — Git Version Control

cPanel → **Git Version Control** → **Create**:

| Field | Value |
|---|---|
| Clone a Repository | on |
| Clone URL | `https://github.com/Kaboniro/polytime.git` |
| Repository Path | `repositories/polytime` |
| Repository Name | `polytime` |

After it's created: **Manage** → **Pull or Deploy** tab → change the
**Checked-Out Branch** to `deploy`.

### 2. Create the Node.js app — Setup Node.js App

cPanel → **Setup Node.js App** → **Create Application**:

| Field | Value |
|---|---|
| Node.js version | 24 (or highest 22.13+) |
| Application mode | Production |
| Application root | `repositories/polytime/server` |
| Application URL | `polytime.online` |
| Application startup file | `server.js` |

**Do not click "Run NPM Install"** — the packages are already in
`node_modules/` one folder up. Installing a second copy can break the app.

### 3. Settings — `.env.production`

In File Manager, go to `repositories/polytime/server/`, copy
`.env.production.example` to `.env.production` and fill it in. Required:

```
SITE_URL=https://polytime.online
ADMIN_PASSWORD=<long random password>
ADMIN_SECRET=<64 random hex characters>
ADMIN_EMAIL=<where sign-in codes are sent>
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_USER=<gmail address>
SMTP_PASS=<Gmail app password>
SMTP_FROM="PolyTime Admin <gmail address>"
CRAWLER_ENABLED=0
```

Generate the secret in cPanel → Terminal:
`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`

(Variables can also go in the Node.js app's **Environment variables** section,
but the cron job below can't see those — the file works for both.)

### 4. Start it

Setup Node.js App → **Restart**, then open `https://polytime.online` and test
an admin login at `/admin/login` (the code arrives by email).

### 5. (Optional) Bring your existing data

The site starts with an empty database. To use your local one instead: stop
the app, upload your local `data/app.db` into `repositories/polytime/server/data/`
(create `data/` if missing), start the app. It contains submitter emails —
never put it under `public_html`.

## Running the crawler

The crawler finds events and files them as **pending** in the admin review
queue; it never publishes anything itself. Pick **one** of these:

### Option A — cron job (recommended on shared hosting)

Shared hosts often kill long-running background processes, so a daily cron
job is more reliable. Keep `CRAWLER_ENABLED=0` in `.env.production`.

1. Find your Node binary: the top of the Setup Node.js App page shows a
   command like
   `source /home/USER/nodevenv/repositories/polytime/server/24/bin/activate`.
   Your node is that same folder + `node`:
   `/home/USER/nodevenv/repositories/polytime/server/24/bin/node`
2. Create the log folder once: `/home/USER/logs`
3. cPanel → **Cron Jobs** → Common Settings **Once Per Day** (or
   `0 3 * * *` for 3 AM), command:

```
cd /home/USER/repositories/polytime/server && /home/USER/nodevenv/repositories/polytime/server/24/bin/node crawler/crawl.js >> /home/USER/logs/polytime-crawl.log 2>&1
```

Replace `USER` with your cPanel username and `24` with your Node version.

Test it first in cPanel → Terminal (prints what it would add, writes nothing):

```
cd ~/repositories/polytime/server && ~/nodevenv/repositories/polytime/server/24/bin/node crawler/crawl.js --dry-run
```

Other flags: `--locales=KR,CN` (only some countries), `--max-pages=60`.

### Option B — built into the app

Set `CRAWLER_ENABLED=1` and restart: the app starts the crawler alongside
itself and runs it on the schedule in `crawler/config.json` (daily). No cron
needed, but it stops whenever the host puts the app to sleep.

### Crawler settings (optional, in `.env.production`)

Without a search provider the crawler only scans the seed sites listed in
`crawler/config.json`.

| Variable | What it does |
|---|---|
| `BRAVE_API_KEY` | Web search via the Brave Search API (paid/credits) |
| `SEARXNG_URL` | Web search via a SearXNG instance hosted elsewhere (JSON output enabled) |
| `TRANSLATE_EMAIL` | Raises the free translation quota (MyMemory) for non-English descriptions |
| `CRAWL_PROXY_CN`, `_KR`, `_JP`, … | HTTP proxy per country for sites blocked from your server |
| `CRAWL_INTERVAL_MINUTES` | Option B only: override the schedule |

## Updating

1. On your computer, in the project (`main` branch): `npm run build:deploy`,
   then `git push origin deploy`.
2. cPanel → Git Version Control → polytime → **Manage** → **Pull or Deploy** →
   **Update from Remote**.
3. Setup Node.js App → **Restart**.

## Troubleshooting

- **Site shows an error / 503** — check `repositories/polytime/server/stderr.log`
  (or the app's log in Setup Node.js App). `PRODUCTION WARNING` lines list
  missing settings.
- **"Cannot find module 'next'"** — the application root must be
  `repositories/polytime/server` (not `repositories/polytime`), and the
  `node_modules` folder must be next to `server/`, not inside it.
- **`node:sqlite` not found** — Node is older than 22.13; pick a newer version.
- **Admin login: "Couldn't send the sign-in email"** — the Gmail app password
  is wrong or revoked; make a new one at
  https://myaccount.google.com/apppasswords.
